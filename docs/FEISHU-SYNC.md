# 飞书发布与知识同步

## 两段式同步

飞书只由博研发布端访问。客户端访问无登录要求的下载地址，使用本地资料回答。合作方不持有博研飞书 App Secret，不需要加入飞书租户，也不直接依赖飞书文档 URL。

发布端持续运行可采用常驻服务或定时任务。首期先实现每 10 分钟扫描指定范围的定时发布；成功后再增加事件加速。每天执行一次完整对账。规模增大后按实际 API 配额调整扫描计划。

客户端启动时、联网恢复时、用户点击时和运行期间每 15 分钟检查一次版本，加入随机抖动。下载器遵守缓存响应并避免重复下载。未运行时不会在用户设备上更新；再次启动后接收最近成功版本。

## 飞书接入

| 内容 | 发布端处理 | 首期范围 |
|---|---|---|
| Wiki 空间和节点 | 分页遍历；Wiki 节点 token 映射真实文档 token；保留目录 | P0 |
| Docx | 读取完整块树、标题、列表、表格和链接；分页完成后生成 Markdown | P0 |
| 普通 Drive 文件夹 | 用户提供根 token 后分页枚举并限制到发布范围 | P0 |
| 文档图片 | 下载为本地资产；保留说明文字；不假设图片内容已被 OCR 理解 | P0，有下载权限的样本 |
| PDF、DOCX 文件附件 | 可随包浏览；提取正文是否计入检索需逐类验收 | P1 |
| Sheets、Base、Slides、画板、妙记 | 列入未支持清单；需对应解析器，不能当普通 Docx 完整处理 | P1 |
| 外部网页链接 | 保留链接文字；不自动抓取链接之外的站点 | P0 |

优先企业自建应用和应用身份，只授权指定发布空间的读取范围。若某类资源无法由应用身份读取，再评估博研专用维护账号的用户授权及刷新机制。客户端不包含合作方角色系统。

配置前逐项核对控制台的 Docx 读取、Wiki 读取、Drive 元数据、附件下载和事件订阅权限；同时配置 API scope 和文档对应用的访问授权。精确 scope 名和接口版本以租户当前开放平台为准，PoC 输出最终最小权限表。

飞书官方 SDK 提供文档订阅接口 `POST /open-apis/drive/v1/files/:file_token/subscribe`，需要同时配置开发者后台事件；SDK 中存在编辑、标题更新、回收站和删除事件。对发布范围内的文档逐项管理订阅。[官方 SDK 接口](https://github.com/larksuite/oapi-sdk-go/blob/99927aa13e271ea9fe03591204aad7bc6a2d869c/service/drive/v1/resource.go)、[事件定义](https://github.com/larksuite/oapi-sdk-go/blob/99927aa13e271ea9fe03591204aad7bc6a2d869c/service/drive/v1/event.go)

PoC 验证租户资源访问、事件覆盖率和接口频率限制。

## 发布流程

1. 获取发布租约，加载根目录、上一成功版本及分页游标。
2. 完整发现文档清单，按资源 token 建立稳定 `document_id`；改标题或移动目录不创建重复文档。
3. 根据 revision、修改时间和内容哈希识别变化。事件仅触发刷新，不作为正文事实来源。
4. 拉取发生变化的文档与资源。读取前后检查 revision；不一致则重试，避免混合两个修订的块。
5. 规范化 Markdown，保留表格上下文、标题路径和来源标识；清除主动脚本、危险协议和无必要的远程资源引用。
6. 生成清单，运行包完整性、来源和智能体配置校验。必需文档读取失败则保留线上旧版，不发布残缺新版本。
7. 将资产上传到不可变的内容哈希路径。最后发布带签名的版本清单；发布清单之前全部文件应已可下载。
8. 写入发布记录、扫描水位和失败诊断。重试相同内容不制造重复版本。

403、429、5xx、超时、分页未完成和根目录不可访问时保留原文档记录。使用有上限的指数退避，遵守服务端重试信息；持续失败进入可重试的失败列表。

正常单文档删除通过删除事件或成功完整对账确认。单次移除超过上一版文档数的 20%，或根目录消失，按异常发布处理，保持旧版并通知博研维护者核对。常规编辑自动发布。

## 知识包 v1 契约

在线更新使用 HTTPS 清单和按哈希寻址的独立文件。离线包可将同一套文件封装为 ZIP，但只允许普通文件和受限相对路径。

| 字段 | 用途 |
|---|---|
| `schema_version` | 清单格式版本，首版为 1 |
| `distribution_id` | 产品发行身份，例如 `boyan-partner` |
| `release_sequence` | 单调递增序号，客户端防止被动降级 |
| `pack_id` | 内容版本唯一标识 |
| `published_at` | 发布时间，UTC RFC 3339 |
| `min_app_version` | 最低客户端版本，不兼容时保留旧包并提示更新软件 |
| `documents` | 文档 ID、标题、相对路径、SHA-256、字节数、来源修订与更新时间 |
| `assets` | 包内资产路径、哈希、字节数和媒体类型 |
| `agents` | 受限智能体文本配置的 ID、版本、路径和哈希 |
| `deleted_document_ids` | 相对上一版移除的来源；全量清单仍为最终依据 |
| `required_document_ids` | 发布时必须存在的基础业务资料 |

签名使用单独 envelope，包含 `key_id`、原始 manifest 文件哈希和 Ed25519 签名。签名覆盖一个固定协议前缀加原始 manifest 字节；验证前不重新序列化 JSON。客户端内置受信公钥，私钥保存在发布端密钥存储。密钥轮换先通过现有可信密钥签名的应用更新建立新信任，不接受下载包自行声明新可信公钥。

Manifest 公开读取，字段不包含飞书凭证、用户目录、个人信息或内部错误栈。飞书源地址仅作为可选溯源元数据；主要引用打开包内原文。

## 客户端更新事务

`发现版本 → 验证签名与兼容性 → 下载缺失文件 → 哈希与路径校验 → 暂存知识库导入 → 验证条目完成 → 切换活动版本 → 清理可回收文件`。

- 文件路径拒绝绝对路径、`..`、符号链接、大小写冲突、设备名和超额大小；同时限制文件数、单文件大小和解压总大小。
- 下载超时、磁盘不足、文档解析失败和索引崩溃都不改变活动版本。
- 内容哈希去重降低下载量；首期可重建 staging 库，避免原地修改导致半完成状态可见。
- 新版只移除官方当前知识中的已删除文档；不删除用户另存副本、导出物或个人知识。
- 回滚重新发布旧内容为更高的 `release_sequence`，不要求用户接受无签名降级。
- 暂存状态持久化，重启后恢复或清理。只有导入作业终态成功才显示“已更新”。

## 内容边界

上传到指定发布范围即进入自动发布流程，博研负责确认资料的交付及继续分发范围。撤下原文或发布新版本只能影响后续更新，无法可靠收回已经下载、复制或导出的资料。

模型推理可能把检索片段发送给用户自选服务商。首次配置时展示该数据流。

## 运维指标

监测扫描成功时间、发布版本、处理文档数、失败数、异常删除比例和端到端发布延迟。发布端日志只保留资源 ID、错误码和耗时；客户端无需向博研发送对话或 Key。首次部署不增加用户行为统计。
