# 飞书发布与知识同步

## Windows 一键发布

维护者双击发布工具的 `launch.cmd`，点击“发布最新资料”。同事使用同一份公司配置、单独交接的发布私钥和各自的飞书授权；发布目录统一共享，版本号从最新有效签名继续。

首次安装和操作见[发布工具说明](../scripts/knowledge-publisher/README.md)。未配置 HTTPS 下载地址时，按钮为“生成发布文件”，结果明确显示“尚未上线”。工具支持写入本机或共享的网站目录，尚不包含对象存储上传适配器。

飞书编辑不自动发布。合作方客户端自动检查和提示新版，点击“立即更新”后才下载、索引和切换。发布工具不增加审批或逐篇确认，不安装常驻服务。

## 本机正文同步

维护端安装 Node.js、项目依赖和 `lark-cli`。飞书应用授权 `wiki:node:retrieve`、`docx:document:readonly`，维护账号须可读取目标知识空间。

```powershell
pnpm knowledge:export --wiki 'https://leboshiedu.feishu.cn/wiki/EqrtwEBRKiZyqZkH7s6cMIB0nQh' --output '.context/feishu/knowledge.json' --include-linked-documents
```

`--wiki` 用于定位所在知识空间；导出范围为该空间的全部顶层节点及其后代。`--name` 指定知识库名称，默认“博研知识库”。导出文件存放于 Git 忽略目录，不提交业务资料或凭证。

`--include-linked-documents` 包含空间正文直接引用的同站点 Docx 和指向 Docx 的 Wiki 文档；按文档 ID 去重，不继续抓取引用文档中的链接，不遍历被引用 Wiki 的子节点。引用读取失败时保留原包。其他站点、幻灯片、多维表格和电子表格仅保留链接，并计入未解析资源。

命令行可选持续扫描：

```powershell
pnpm knowledge:export --wiki 'https://leboshiedu.feishu.cn/wiki/EqrtwEBRKiZyqZkH7s6cMIB0nQh' --output '.context/feishu/knowledge.json' --include-linked-documents --watch
```

`--watch` 启动后立即扫描，每轮完成后等待 600 秒。`--interval` 可设为 60–86,400 秒。扫描串行执行，失败后保留原包并在下一轮重试；Ctrl+C 等当前扫描结束后退出。电脑休眠、关机或进程退出期间不扫描。不安装系统计划任务，不上传资料。每轮输出新增、修改、删除、正文、空页面和未解析资源文档数；内容未变化时不重写输出文件。

输出路径使用独占 `.lock` 文件。异常终止后，仅在确认文件内 PID 对应的发布进程已退出时移除该锁。旧包校验失败、入口节点不在完整目录中、输出属于其他空间时拒绝替换。

删除与正文清空的文档合计超过上一成功版本文档数的 20% 时阻止发布。核对变更后，以单次导出参数 `--accept-removals-from <上一成功包的完整 packId>` 放行；该参数不得与 `--watch` 同用。

在 Cherry 的知识库页面点击“导入飞书知识包”，选择生成的 JSON 文件。索引完成后自动选中新版本。可在“检索测试”中验证召回，也可将该知识库绑定到使用者配置的助手。

更新资料后重新运行导出命令，再导入同一文件。内容与修订未变化时复用原知识库；变化时建立独立版本。新版索引成功且对话生成结束后，原活动知识库的助手和智能体绑定迁移到新版；其他知识库绑定、提示词、模型配置和历史对话保持不变。旧版本继续保留。手动指定的旧版引用和用户另存副本不自动替换。

活动知识库使用知识包名称，不追加版本哈希。旧版本保留哈希后缀以区分；用户自行修改的旧库名称保持不变。完整版本号保存在导入记录中。

- 原生 Docx 正文转换为 Markdown，保留来源 URL、目录路径、文档 ID 和修订号。
- 只有标题的页面保存在包清单中，不建立正文索引。
- 图片、附件、嵌入资源及评论不下载、不解析；导入结果展示含未下载资源的文档数。图片内文字不计入正文检索。
- 非 Docx 节点、读取失败、分页异常时停止导出，保留已有输出文件。
- 上限：2,000 篇文档、30 层目录、20 MiB 知识包。
- SHA-256 校验检测包内容变更，不证明发布者身份。本地未签名 JSON 仅供维护者手动导入；已接受签名更新的空间拒绝未签名覆盖。
- 通过 Cherry 原生知识服务建立 BM25 索引，不调用付费 embedding 模型。
- 索引失败保留旧版。重新导入可重建失败暂存库，或接收已经完成的暂存版本。
- 未配置更新源时使用手动导入；签名发布和客户端自动更新使用下述配置。仓库不包含正式下载地址或发布私钥。

### 本机验收

1. 导出包含知识空间 18 篇 Docx；启用直接引用后共 22 篇，其中 18 篇含正文。
2. 导入后原生知识库显示 18 篇已完成条目，来源含飞书 URL 和目录。
3. 原包再次导入不创建重复知识库。
4. 篡改包正文且不更新校验值时拒绝导入。
5. 新版导入失败时旧版仍可检索，重试成功后可选择新版。
6. 用户模型配置、自建知识库和历史对话保持可用。
7. 引用文档只读取一层；重复引用只产生一份正文，不跨站点或递归扩大范围。
8. 重复导出不修改知识包；完整扫描中的新增、修改、移除具有对应统计。
9. 读取失败、入口缺失、大量删除或清空、旧包损坏时保持输出不变。

## 签名发布与更新提示

维护端使用独立 Ed25519 PKCS#8 PEM 私钥。私钥保存于源码仓库和公开发布目录之外，并限制文件访问权限；不复用 Git 提交签名密钥。客户端只包含 SPKI PEM 公钥。签名和验证使用 [Node.js Crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html)。

```powershell
pnpm knowledge:export --wiki 'https://leboshiedu.feishu.cn/wiki/EqrtwEBRKiZyqZkH7s6cMIB0nQh' --output '.context/feishu/knowledge.json' --include-linked-documents --release-directory '.context/feishu/releases' --signing-key 'D:\BoyanSecrets\knowledge-release.pem' --key-id 'boyan-2026' --distribution-id 'boyan-partner' --min-app-version '2.0.14'
```

发布目录包含不可变的 `<sha256>.json` 知识包和 `latest.json` 签名清单。相同知识和最低应用版本不产生新发布序号。回滚内容必须重新发布为更高序号。发布目录及 `latest.json` 必须持久保存，不得通过删除清单重置序号。存在 `release.lock` 时拒绝并发发布；异常退出后仅在确认锁内 PID 已退出时移除锁。

将发布目录映射到 HTTPS 静态下载地址。上传对象存储时先上传哈希文件，确认可下载后再替换 `latest.json`。不得上传源文件、锁文件、私钥、飞书凭证或维护日志。当前命令生成本地发布目录；对象存储上传和常驻任务部署由运行环境配置。

构建前设置 `resources/feishu-update.json`：

```json
{
  "distributionId": "boyan-partner",
  "spaceId": "7610776951925509072",
  "manifestUrl": "https://YOUR_DOWNLOAD_HOST/knowledge/latest.json",
  "keys": {
    "boyan-2026": "YOUR_ED25519_SPKI_PUBLIC_KEY_PEM"
  }
}
```

文件为 `null` 时关闭自动更新，界面显示“尚未配置自动更新”。配置编入主进程；下载内容无法改变受信公钥。正式构建只接受无账号、密码、查询参数和片段的 HTTPS 地址，拒绝重定向。请求使用 [Electron 网络接口](https://www.electronjs.org/docs/latest/api/net)，不发送登录凭证。

开发实例可通过 `BOYAN_FEISHU_UPDATE_CONFIG` 指定本机配置文件；仅非打包应用允许数值回环地址的 HTTP 服务。正式成品忽略此环境变量。

客户端启动后约 5 秒检查一次，成功后每 15 分钟加 0–30 秒随机延迟检查。网络恢复最多约 5 秒后触发检查；检查失败后以 1、2、4、8、15 分钟间隔重试。检查仅读取签名清单，不下载正文或建立索引。主窗口显示新版提示和“立即更新”，知识库页面提供当前状态和最后更新时间。未运行或电脑休眠时不检查。

点击“立即更新”时重新验证清单，并匹配用户看到的版本序号；期间出现更新版本则提示新版，等待再次点击。下载或索引失败保留旧版，用户可再次点击重试。重启和后台检查不会自动应用待更新版本。

每次请求限制 60 秒；签名清单上限 32 KiB，知识包上限 20 MiB，读取响应流时持续检查大小。客户端先校验可信签名、发行身份、空间、最低应用版本和单调序号，再下载正文。相同序号不得对应不同清单。已经验证过的较高序号持久保存，下载或索引失败不允许回退到更低序号。

同一进程复用已验证的相同哈希知识包；重启后重新校验下载包。重复检查共享同一个任务。更新、索引和助手绑定迁移不消耗模型额度。

索引成功后等待正在生成的普通对话及智能体任务结束，再在数据库事务内切换活动版本、库名和助手绑定。等待超过 120 秒时保留旧版与暂存版，下次检查继续。退出程序取消下载与等待；重启后重新校验，复用完整暂存版或重建失败索引。

### 更新验收

1. 合法签名清单触发新版提示；点击之前不下载或导入，点击完成后原活动版本绑定的助手和智能体使用新版。
2. 断网、服务错误、截断下载、超额响应及索引失败保留旧资料；恢复后重试成功。
3. 未知密钥、修改签名、修改清单、修改正文、错误空间及发行身份均拒绝激活。
4. 重启后仍拒绝低序号和同序号冲突；更高序号发布旧内容可合法回滚。
5. 活跃对话结束前不切换版本；历史来源文件保留。
6. 私人知识库、提示词、用户 Key、对话和原有模型配置保持不变。
7. 未配置正式更新源时不发起后台下载。

## 两段式同步

飞书只由博研发布端访问。客户端访问无登录要求的下载地址，使用本地资料回答。合作方不持有博研飞书 App Secret，不需要加入飞书租户，也不直接依赖飞书文档 URL。

发布端按维护者点击执行一次完整扫描和发布，不默认配置常驻服务或定时任务。规模增大后按实际 API 配额调整读取策略。

客户端启动时、联网恢复时、用户点击时和运行期间每 15 分钟检查一次版本，加入随机抖动。同一进程复用用户发起下载后已校验的知识包。未运行时不会在用户设备上更新；再次启动后提示最近成功发布的版本。

## 飞书接入

| 内容 | 发布端处理 | 首期范围 |
|---|---|---|
| Wiki 空间和节点 | 分页遍历；Wiki 节点 token 映射真实文档 token；保留目录 | P0 |
| Docx | 读取完整块树、标题、列表、表格和链接；分页完成后生成 Markdown | P0 |
| 普通 Drive 文件夹 | 用户提供根 token 后分页枚举并限制到发布范围 | P0 |
| 文档图片 | 下载为本地资产；保留说明文字；不假设图片内容已被 OCR 理解 | P0，有下载权限的样本 |
| PDF、DOCX 文件附件 | 可随包浏览；提取正文是否计入检索需逐类验收 | P1 |
| Sheets、Base、Slides、画板、妙记 | 列入未支持清单；需对应解析器，不能当普通 Docx 完整处理 | P1 |
| 外部网页链接 | 保留链接文字；不自动抓取链接之外的站点 | P0 |

优先企业自建应用和应用身份，只授权指定发布空间的读取范围。若某类资源无法由应用身份读取，再评估博研专用维护账号的用户授权及刷新机制。客户端不包含合作方角色系统。

配置前逐项核对控制台的 Docx 读取、Wiki 读取、Drive 元数据、附件下载和事件订阅权限；同时配置 API scope 和文档对应用的访问授权。精确 scope 名和接口版本以租户当前开放平台为准，PoC 输出最终最小权限表。

飞书官方 SDK 提供文档订阅接口 `POST /open-apis/drive/v1/files/:file_token/subscribe`，需要同时配置开发者后台事件；SDK 中存在编辑、标题更新、回收站和删除事件。对发布范围内的文档逐项管理订阅。[官方 SDK 接口](https://github.com/larksuite/oapi-sdk-go/blob/99927aa13e271ea9fe03591204aad7bc6a2d869c/service/drive/v1/resource.go)、[事件定义](https://github.com/larksuite/oapi-sdk-go/blob/99927aa13e271ea9fe03591204aad7bc6a2d869c/service/drive/v1/event.go)

PoC 验证租户资源访问、事件覆盖率和接口频率限制。

## 发布流程

1. 获取发布租约，加载根目录、上一成功版本及分页游标。
2. 完整发现文档清单，按资源 token 建立稳定 `document_id`；改标题或移动目录不创建重复文档。
3. 根据 revision、修改时间和内容哈希识别变化。事件仅触发刷新，不作为正文事实来源。
4. 拉取发生变化的文档与资源。读取前后检查 revision；不一致则重试，避免混合两个修订的块。
5. 规范化 Markdown，保留表格上下文、标题路径和来源标识；清除主动脚本、危险协议和无必要的远程资源引用。
6. 生成清单，运行包完整性、来源和智能体配置校验。必需文档读取失败则保留线上旧版，不发布残缺新版本。
7. 将资产上传到不可变的内容哈希路径。最后发布带签名的版本清单；发布清单之前全部文件应已可下载。
8. 写入发布记录、扫描水位和失败诊断。重试相同内容不制造重复版本。

403、429、5xx、超时、分页未完成和根目录不可访问时保留原文档记录。使用有上限的指数退避，遵守服务端重试信息；持续失败进入可重试的失败列表。

正常单文档删除通过删除事件或成功完整对账确认。单次移除超过上一版文档数的 20%，或根目录消失，按异常发布处理，保持旧版并通知博研维护者核对。普通修改在维护者点击发布时统一处理。

## 签名 JSON 协议 v1

正文沿用本机 `FeishuPackageSchema`；一个发布版本包含一个完整 JSON 正文文件。资源下载、分文件增量和 ZIP 包另行扩展，不属于此协议。

原始清单字段为 `schemaVersion`、`distributionId`、`spaceId`、`sequence`、`publishedAt`、`minAppVersion`、`packId`、`sha256`、`bytes`。正文文件名固定为清单中的 `<sha256>.json`，与 `latest.json` 同目录；清单不得指定任意下载地址或本地写入路径。

`latest.json` 是 envelope，字段为 `keyId`、`manifest`、`sha256`、`signature`。`manifest` 保存原始清单字节的 Base64，`sha256` 为这些字节的哈希，`signature` 为 Ed25519 签名的 Base64。签名输入为 UTF-8 `boyan-feishu-release-v1\n` 前缀加原始清单字节，验签前不重新序列化 JSON。

## 文件清单协议扩展

在线更新使用 HTTPS 清单和按哈希寻址的独立文件。离线包可将同一套文件封装为 ZIP，但只允许普通文件和受限相对路径。

| 字段 | 用途 |
|---|---|
| `schema_version` | 清单格式版本，首版为 1 |
| `distribution_id` | 产品发行身份，例如 `boyan-partner` |
| `release_sequence` | 单调递增序号，客户端防止被动降级 |
| `pack_id` | 内容版本唯一标识 |
| `published_at` | 发布时间，UTC RFC 3339 |
| `min_app_version` | 最低客户端版本，不兼容时保留旧包并提示更新软件 |
| `documents` | 文档 ID、标题、相对路径、SHA-256、字节数、来源修订与更新时间 |
| `assets` | 包内资产路径、哈希、字节数和媒体类型 |
| `agents` | 受限智能体文本配置的 ID、版本、路径和哈希 |
| `deleted_document_ids` | 相对上一版移除的来源；全量清单仍为最终依据 |
| `required_document_ids` | 发布时必须存在的基础业务资料 |

签名使用单独 envelope，包含 `key_id`、原始 manifest 文件哈希和 Ed25519 签名。签名覆盖一个固定协议前缀加原始 manifest 字节；验证前不重新序列化 JSON。客户端内置受信公钥，私钥保存在发布端密钥存储。密钥轮换先通过现有可信密钥签名的应用更新建立新信任，不接受下载包自行声明新可信公钥。

Manifest 公开读取，字段不包含飞书凭证、用户目录、个人信息或内部错误栈。飞书源地址仅作为可选溯源元数据；主要引用打开包内原文。

## 客户端更新事务

`发现版本 → 验证签名与兼容性 → 下载缺失文件 → 哈希与路径校验 → 暂存知识库导入 → 验证条目完成 → 切换活动版本 → 清理可回收文件`。

- 文件路径拒绝绝对路径、`..`、符号链接、大小写冲突、设备名和超额大小；同时限制文件数、单文件大小和解压总大小。
- 下载超时、磁盘不足、文档解析失败和索引崩溃都不改变活动版本。
- 内容哈希去重降低下载量；首期可重建 staging 库，避免原地修改导致半完成状态可见。
- 新版只移除官方当前知识中的已删除文档；不删除用户另存副本、导出物或个人知识。
- 回滚重新发布旧内容为更高的 `release_sequence`，不要求用户接受无签名降级。
- 暂存状态持久化，重启后恢复或清理。只有导入作业终态成功才显示“已更新”。

## 内容边界

维护者点击发布后读取指定范围内的资料，博研负责确认资料的交付及继续分发范围。撤下原文或发布新版本只能影响后续更新，无法可靠收回已经下载、复制或导出的资料。

模型推理可能把检索片段发送给用户自选服务商。首次配置时展示该数据流。

## 运维指标

监测扫描成功时间、发布版本、处理文档数、失败数、异常删除比例和端到端发布延迟。发布端日志只保留资源 ID、错误码和耗时；客户端无需向博研发送对话或 Key。首次部署不增加用户行为统计。
