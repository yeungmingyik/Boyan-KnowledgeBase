# 构建与交付

## 成品矩阵

| 平台 | 首期制品 | 使用方式 |
|---|---|---|
| Windows x64 | 签名安装程序、便携程序或 ZIP | 正常安装；或解压/直接启动，数据行为在界面说明 |
| Windows arm64 | P1 安装与便携包 | 依据实际设备需求追加测试 |

Windows 便携版复用上游 portable 目标，验收实际用户数据路径。模型 Key 默认保存在独立凭证存储。完整 U 盘便携模式需要单独的凭证迁移与加密方案。

## 工具链

v2.0.14 的 Node 引擎范围为 `>=24.11.1 <24.16.0`，packageManager 为 pnpm 11.8.0；主分支参考提交使用 pnpm 12.3.4。构建以选定提交自带版本、锁文件和安装说明为准，不能混用。[稳定版 package.json](https://github.com/CherryHQ/cherry-studio/blob/d33b9b0266bda30d0e4715ae16650eee7b845d70/package.json)

Windows 使用 PowerShell 7，在 Windows 机器或 runner 上构建、签名及验证安装。原生依赖按目标 Windows 架构构建。博研发行任务仅选择 Windows 构建目标。

CI 依次完成依赖锁定、适用静态检查、针对性测试、打包、签名、成品校验及干净 Windows 机器安装验证。生产发布私钥只提供给受保护的发行流程，普通 PR 不接触。

## 产品身份

独立定义产品名、应用 ID、协议名称、用户数据目录、崩溃诊断说明、图标与应用更新源。不能继续指向官方 Cherry 的二进制更新地址，否则更新可能覆盖博研定制版。

不默认依赖 Cherry Cloud、官方付费权益或官方签名服务。v2.0.14 的发行说明提到自定义构建登录 Cherry Cloud 的签名要求；首期使用合作方自己的服务商配置即可，遵守官方服务接入要求。[发行说明](https://github.com/CherryHQ/cherry-studio/releases/tag/v2.0.14)

## 两条版本线

| 类型 | 版本 | 更新策略 |
|---|---|---|
| 应用 | 博研 SemVer + 上游基线记录 | 用户确认安装升级；安装版和免安装版分别验证适用更新流程 |
| 知识与智能体文本 | 单调序号 + pack ID | 默认自动更新，可手动检查或导入离线包 |

普通知识更新不更改应用可执行代码。应用更新前备份数据库，迁移只向前追加；回退应用需要确认数据库兼容，必要时恢复升级前备份。

便携制品如不支持可靠原位自更新，采用下载新程序并显式迁移/复用既有数据目录。对外承诺的更新方式以实际验证结果为准。

## 托管和发布器

首期使用博研控制的发布任务和 HTTPS 对象存储或静态下载域名。GitHub Releases 可作为成品镜像和源码来源，合作方的默认知识下载地址需实测国内访问表现。

发布器的最小状态包括发布根目录、资源身份、revision/hash、扫描游标、失败记录、最新成功版本和发布锁。可用 SQLite 存储；服务中断恢复后先对账再发布。

客户端只内置发布公钥和下载基地址。对象存储写入凭证、飞书 App Secret、Windows 签名材料和知识包签名私钥分别管理，不合并为一个全权限密钥。

## 发布清单

- 对应平台安装版、免安装版及 SHA-256 校验值。
- 内置知识包、签名清单、可手动导入的离线知识包。
- 软件版本、上游 commit、知识包版本和构建依赖版本。
- 按选定许可路径准备的源码、构建说明、许可证及第三方声明。
- 简短使用说明：配置 Key、打开业务入口、查看引用、检查更新、导出资料。
- 脱敏诊断导出方法和博研支持渠道。

## 成本结构

公司承担资料发布任务、存储流量、域名、Windows 构建 runner 和代码签名等成本；合作方承担自己的模型调用。费用按文档规模、更新频次和下载量核算。

月度发布成本约等于运行资源 + 存储 GB 月 + 下载流量 + 请求费用；下载量主要取决于首装人数 × 内置/完整包大小，以及在线客户端数 × 每期增量字节。实际选供应商时再核实价格与可用区域。
