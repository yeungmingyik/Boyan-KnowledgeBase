# 产品需求

## 产品定义

BoyanKB 是博研交付给合作方的业务知识桌面客户端。合作方通过软件了解博研的业务、组织本地落地方案和制作沟通材料。产品基于 Cherry Studio 二次开发，面向 Windows，允许合作方继续分发。

业务背景包括中小学科创教育、成人 AI 培训、中小学 AI 营地和 AI 黑客松。具体课程、合作机制、报价、交付条件和知识产权服务，以博研发布的飞书资料为准。

## 用户与成功结果

| 用户 | 要完成的事情 | 成功结果 |
|---|---|---|
| 首次接触博研的合作方 | 了解业务与合作方式 | 能找到业务说明、条件和原始依据 |
| 城市合作负责人 | 判断本地资源如何落地 | 获得有假设、有步骤、有资料依据的行动草案 |
| 合作方销售或项目人员 | 准备沟通、课程或活动材料 | 获得可编辑草稿，事实与建议清楚区分 |
| 博研资料负责人 | 在飞书更新内容 | 无需重新打包软件即可把资料同步给合作方 |
| 博研产品维护者 | 发布版本和维护上游 | 可复现构建，可定位知识与软件版本，可回退 |

## 首次使用旅程

1. 安装或解压后打开客户端，看到博研品牌首页及业务入口。
2. 内置知识包在后台建立本地索引；进度和失败原因可见，仅在索引完成后显示“已就绪”。
3. 用户选择服务商和模型，输入自己的 API Key，执行一次明确的连接测试。测试是否可能计费在按钮旁提示。
4. 未配置 Key 时仍可浏览资料并进行本地关键词检索；配置完成后可使用业务智能体。
5. 选择“了解博研”或“城市落地规划”，输入问题，获得附本地来源引用的回答。
6. 软件展示知识更新时间；后续自动获取知识新版本，用户也可立即检查更新或导入离线知识包。

## 知识与内容

唯一纳入的飞书范围由博研指定。维护者修改资料后点击一次发布，不增加审批或逐篇确认。客户端自动检查新版，由合作方点击“立即更新”后下载和应用。发布目录之外的内容不进入知识包，目录误删、权限异常或解析失败不被当作正常批量删除。

首期优先 Docx 和 Wiki 节点中承载的 Docx；正文、标题、列表、表格、链接必须保留。图片和附件按支持矩阵处理；不支持的内容明确列出，不能宣称全文已同步。资料可继续传播是既定产品前提。

## 质量目标

验收基准： 100 篇中文样本文档、纯文本合计不超过 20 MB、单包不超过 100 MB；实际样本超出时重新估算。

| 指标 | 目标 |
|---|---|
| 首次知识准备 | 参考设备上 120 秒内完成；长任务可恢复，不能阻塞设置 Key |
| 中文检索 | 60 道有标准依据的问题，Recall@5 ≥ 90% |
| 回答可依据原文核实 | 有答案问题的抽样断言支持率 ≥ 90% |
| 引用指向 | 引用路径有效率 100%，内容支持回答的比例 ≥ 95% |
| 无依据问题 | 20 道题中明确说明资料不足的比例 ≥ 95% |
| 更新提示 | 发布成功、客户端运行联网时，发现新版本不超过 15 分钟加 30 秒随机延迟；用户自行决定安装时间 |
| 更新完整性 | 所有故障演练中均无半更新知识库成为活动版本 |
| 使用限制 | 无博研账号、无飞书账号、无席位授权也可配置模型使用 |

模型输出质量分服务商记录；网络、供应商故障不混入本地检索延迟。详细口径见 [验收计划](ACCEPTANCE.md)。

## 产品决策

- 飞书资料经博研发布端分发；客户端仅访问知识包下载源。
- 知识更新和应用更新使用独立版本；更新资料通常不需要安装新版软件。
- 内置智能体随知识发布包更新，但只包含受限的文本配置，不携带可执行脚本或新 SKILL。
- 本地全文检索先行；若中文检索未达到门槛，先改善分词、标题、别名和查询策略，再评估向量检索。
- 回答中的商业事实只能来自资料；地域调研、市场规模和收益预测须标明数据来源与假设。
