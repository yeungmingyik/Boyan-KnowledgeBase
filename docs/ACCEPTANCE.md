# 验收计划

## 参考条件

Windows 11 x64、4 核 CPU、16 GB 内存、SSD。开发、功能与发行验收均在 Windows 执行。最低操作系统版本以选定 Electron 版本及安装测试结果为准。

基准知识集包含约 100 篇中文文档、20 MB 以内纯文本和 100 MB 以内完整资源。若实际规模明显不同，性能目标随基准一起重定，不降低功能正确性要求。

## 真实业务评测

由博研资料负责人准备 60 道有答案问题和 20 道缺乏依据的问题。有答案问题覆盖所有业务类型、单文档事实、跨文档组合、同义表达、数字、表格与来源冲突；每题记录标准来源和可接受回答要点，不要求模型逐字复现。

| 指标 | 计算方法 | 门槛 |
|---|---|---|
| Recall@5 | 前 5 个检索结果包含至少一个标注来源的问题数 / 60 | ≥ 90% |
| 事实支持率 | 人工抽查的有依据事实断言数 / 全部被抽查事实断言数 | ≥ 90% |
| 引用有效率 | 能打开正确包内文件及章节的引用数 / 全部引用数 | 100% |
| 引用支持率 | 原文实际支持对应说法的引用数 / 全部评测引用数 | ≥ 95% |
| 缺失依据识别 | 明确指出资料不足且不编造答案的问题数 / 20 | ≥ 95% |
| 数字忠实性 | 与引用来源一致的报价、数量、时长等数字 / 此类数字 | 100%，不存在时不杜撰 |

至少两种用户自配模型独立记录结果；不支持工具调用时也要验证基础检索路径。模型供应商故障、限流和额度不足单独统计。

## P0 场景

| 编号 | 场景 | 预期 |
|---|---|---|
| T01 | 新电脑无账号、无飞书、无 Key | 能浏览内置资料，建立索引后能全文检索 |
| T02 | 配置有效及无效 API Key | 有效可问答，无效给出明确且不泄露 Key 的错误 |
| T03 | 在飞书新增、编辑、改名、移动、删除文档 | 版本正确变化，不重复、不漏标题或表格 |
| T04 | Wiki 多页及多层目录 | 完整遍历且保留真实来源身份 |
| T05 | 飞书 403、429、5xx、部分分页失败 | 不把失败文档当作正常删除，不发布不完整版本 |
| T06 | 断网、磁盘不足、导入失败或中途关机 | 旧版仍可查询；重启可恢复，状态准确 |
| T07 | 篡改文件或签名、下载旧序号清单 | 拒绝激活；合法更高序号回滚包可用 |
| T08 | 恶意相对路径、ZIP 炸弹、符号链接 | 在写入用户目录外之前拒绝；资源限额生效 |
| T09 | 更新官方知识和智能体 | 用户 Key、对话、个人知识与个人副本内容不变 |
| T10 | 对话生成期间切换版本 | 回答及引用仍指向固定来源版本 |
| T11 | 飞书链接对合作方不可访问 | 本地引用仍完整可用 |
| T12 | 文档包含提示注入 | 不读取 Key、不运行 shell、不改变工具策略 |
| T13 | 安装版和便携版并行使用 | 产品目录明确；不会覆盖原版 Cherry Studio 数据 |
| T14 | 两个版本客户端同时存在 | 不并发修改同一数据库；实例或锁保护生效 |
| T15 | 浅深色、高 DPI、中文输入法、键盘操作 | 核心路径无截断、焦点可见、表格可读 |
| T16 | 签名后的 Windows 成品 | 在干净 Windows 机器完成安装、首次运行、升级和卸载检查 |
| T17 | 更新站不可达 | 现有资料可用，失败可见；恢复联网后继续 |
| T18 | 不兼容知识包或智能体配置含执行字段 | 保留旧包；拒绝未知高风险字段，不能执行包内代码 |

## 性能与更新目标

- 首次索引参考数据集 ≤ 120 秒，本地搜索 p95 ≤ 1 秒；测试期间不把模型延迟计入搜索时间。
- 飞书普通文档变化到联网运行客户端新知识可用 p95 ≤ 30 分钟，至少测 20 次更新，包含轮询等待和客户端索引时间。
- UI 采用同机、同数据、同窗口尺寸对比原版：空闲 CPU 不持续多于原版 2 个百分点，输入延迟 p95 不恶化超过 20%。这些阈值在 M1 采样建立基线后确认。
- 不开启长期高频动效或后台模型调用；更新检查不消耗用户模型 Token。

## Windows 发布向导

| 场景 | 预期 |
|---|---|
| 缺少 Node.js 或飞书 CLI | 显示缺失组件及安装入口，不能进入下一步 |
| 飞书未登录、授权不足、配置名称变化 | 不允许继续；连接检查通过后显示当前账号 |
| 缺少配置、密钥或统一目录 | 停留在选择资料步骤，提示对应字段 |
| 重新打开已有配置 | “继续上次发布”重新验证飞书连接，通过后进入发布页 |
| 未设置 HTTPS 地址 | 只显示“生成发布文件”，完成后明确资料尚未上线 |
| 发布成功、失败、重复点击 | 实时显示阶段；运行中禁用导航和发布；失败后允许修正并重试 |
| 多人使用相同发行配置与目录 | 使用各自飞书登录，连续生成版本；并发发布不得覆盖已有清单 |
| 普通尺寸、放大窗口和键盘操作 | 内容无重叠，路径可编辑和选择，主操作始终可见 |

## 工程检查

界面验收使用 cherry-electron-dev，在 Windows 实际 Electron 窗口中检查首页、对话、知识中心、设置及主要弹窗。记录软件提交、系统版本、窗口尺寸、缩放比例、主题和证据路径；检查浅深色、中文输入法、键盘焦点、减少动态效果及不透明模式。性能比较使用同机同场景基线。

代码变更使用对应上游版本要求的 lint、类型检查和受影响测试。上游参考提交要求代码修改执行 `pnpm lint` 及相关测试，文档修改执行 `pnpm docs:check`。命令以目标 checkout 的 package.json 和贡献规则为准。

新增测试集中覆盖版本切换、包校验、路径限制、知识来源映射和用户数据保留。静态配色的小改动通过必要的界面验收确认，不编写只断言实现常量的测试。

规划文件检查内部链接、规范一致性和依赖引用。产品构建与运行测试在源码环境执行。

## 发行门槛

所有 P0 场景通过；业务负责人认可真实评测；签名与许可证材料准备完成；知识更新失败和应用升级失败均有可演练恢复方法。任何“已通过”都要有平台、软件 commit、知识版本、模型和结果记录。
