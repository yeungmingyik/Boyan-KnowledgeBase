# 开发路线图

## 估算前提

按一名熟悉 TypeScript、Electron 的主开发，博研提供资料负责人并有兼职设计/测试支持估算。首期预计 6–8 周，约 30–40 个开发人日；设计与业务验收约 8–12 人日分布在各阶段。排期包含模型兼容、同步接入和签名准备的风险缓冲。

不安排账号、权限、多租户或运营后台。服务器只承担资料发布任务，合作方问答直接使用自己的模型配置。

## 阶段及退出条件

| 阶段 | 预计 | 任务 | 必须产物与退出条件 |
|---|---|---|---|
| M0：基线与资料 | 2–3 日 | 选许可路径、建代码仓库、确认技能、清点样本、在两端跑原版 | 固定提交；构建记录；发布根目录；真实样本与设备清单 |
| M1：关键 PoC | 4–5 日 | 无 Key 导入 BM25、中文检索、飞书读取、知识版本切换、两种模型、模板注册 | 20 篇样本完整读取；知识可用；引用可打开；发现限制有处理结论 |
| M2：知识交付链路 | 7–9 日 | 飞书发布器、清单签名、静态托管、自动检查、事务更新和恢复 | 增删改与离线包跑通；断电/失败不破坏旧知识 |
| M3：业务入口与主题 | 7–9 日 | 四个智能体、首启配置、主题、来源预览、状态与个人副本 | Windows/macOS 主流程可用；所有商业断言有依据 |
| M4：发行与验收 | 6–8 日 | 安装/便携构建、签名、公证、升级迁移、真实业务评测 | 通过 P0 验收；安装包与源码对应；发布和回滚演练完成 |
| 缓冲 | 4–6 日 | 修复跨平台差异、内容问题、模型差异与性能瓶颈 | 关闭阻断项，形成可交付版本 |

范围随 M1 的实测结果收敛。若中文全文检索不足，应在 M1 决定补检索能力，检索质量达标后进入完整界面实施。

## 范围控制

依赖选型以功能、吞吐和维护需求为准。首期不引入 PostgreSQL、Redis 或独立向量服务作为默认依赖；发布端单实例可采用本地 SQLite 状态和对象存储，未来有实际吞吐瓶颈时再扩展。

阶段结束维护验收结果和风险记录。AGENTS.md 仅保留长期规则，技能按任务触发。
